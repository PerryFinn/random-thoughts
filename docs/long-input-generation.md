# 完整长输入与有限分批生成

本切片承接 [#31](https://github.com/PerryFinn/random-thoughts/issues/31) 与父规格 [#20](https://github.com/PerryFinn/random-thoughts/issues/20)，基于本地 `2df5a96`。2026-10-16 只读核对远端 main 为 `123948d`，#31 仍被开放的 #28 阻塞；本地已有 #28／#29／#30 的前置实现，不改变远端阻塞状态。

## 同一流程与完整输入

界面和主要业务测试共用 `DailyReportFlow.send`，三协议仍共用事实提取、事实归并和六章节成文三个业务意图。直接预算内沿用单次生成；预算外先离线建立完整有限计划，不能裁尾或跳过当天内容。

优先保留会话和工作轮次边界。超长单轮按 Unicode 文本边界拆分，保留全部字符、角色、报告日／原始日期、顺序、临时会话／轮次关联、片段序号及总数、结果状态。部分片段不能证明整轮完成；事实条目的完成判断必须等相关整轮全部片段整合。

中间结果为可解析事实条目，包含有效直接上游引用、临时轮次关联、状态及有据摘要，不是六章节日报。每节点必须明确覆盖全部必要上游，事实条目只能引用对应上游；无团队相关内容须明确标记。原文片段的覆盖关系在本机逐层合并，最终根覆盖全部当天输入；关联仅存当次内存，不增加逐条证据 UI、档案或数据库字段。

片段显式携带 `association`（`session/order`），事实条目的 `turns` 复制该关联，不能使用数字片段 ID、会话编号或局部序号。结构化 schema 约束关联格式；当前节点覆盖中没有任何完整工作轮次时，只允许 `uncertain`／`unconfirmed`，不能生成 `confirmed`。提取及归并都按本机覆盖计算选择该 schema；有完整轮次仍不代表事实已完成，执行器继续逐条检查有效引用、引用所对应的关联及整轮全部片段。非结构化请求使用相同的明确指令，违规响应仍失败，不机械改写状态或关联。

新增关联字段随实际输入参与离线预算。规划及发送使用包含全部状态的较大固定 schema 预留，较小的未确认状态 schema 不扩大已确认计划；不为这项修复添加重试或 AI 修复请求。格式约束依据 [OpenAI Structured Outputs 的 string pattern 与 enum 支持](https://developers.openai.com/api/docs/guides/structured-outputs)，不据此声明任意模型／中转组合兼容。

成文时明确区分工作状态与行动意图：失败、未完成、阻塞、测试尚未执行或缺少证据本身不是 TODO，也不能据此推导修复、重测、验证或发布计划。已尝试的请求不代表用户再次要求重试；只保留材料中明确的未来承诺、仍待执行的用户请求／已认可行动或显式 TODO，并保留实际日期。未解决状态归入问题与风险；没有符合条件的未来行动时 `plans` 必须为空字符串。此规则由直接与分批成文共用的指令传递，不新增语义过滤、额外审核或修复请求；真实语义仍须通过 #36 的逐份报告复核。

成文必须保留每个关键阻塞的原因、原文影响范围和确定性，即使它只在大量重复进度中出现一次。报告阻塞的会话／轮次／条目是证据来源，不自动限定受影响工作事项；不同事项也可以共享阻塞。成果和行动按事项组织，只有状态的阻塞事实放风险章节，不能据此编造成果、决策或理由；材料明确表达的决策及理由仍应保留。风险章节保留原文因果含义及材料中明确关联的范围，范围可以由同一来源上下文跨句明确表达；草稿／审核标签与事实引用本身不是影响范围断言。没有“仅 X 受影响”等明确范围陈述时，只在风险章保留该阻塞陈述，避免在概览、完成事项或产出重复改写；不能把“这些规则”等代词替换成邻近条目／规则族编号，也不能凭“共享”擅自扩大为全部事项。直接与分批成文共用这条规则，并通过“范围未明确时保留原句／跨句明确范围时保留限定”的成对示例说明，示例不作为报告事实。本机覆盖和引用校验继续验证证据来源，不承担自然语言影响范围判断。

抽取／归并时，每项因果阻塞独立为事实，与同处一轮的草稿、进度和审核结果分开，优先于压缩重复进度输出。保留阻塞的原始原因、影响范围表述与确定性；引用和轮次记录报告位置，不自动限定受影响对象。未明确范围不能成为丢弃确定阻塞的理由，应保留原指代并说明范围未明确，不自动把报告条目当作受影响对象。该分离不修改事实字段、覆盖、引用或整轮状态校验。

## 预算与有限收敛

沿用真实离线双编码、每独立文本块取较大值及每请求 1,024 token 预留。中间可见预算由后层输入空间和启动时 O 反推，并与含思考的 O 分开；O 不作为可见正文容量承诺。中间节点作为协议原生独立文本块发送，分别计数与限制，后层按每块允许的最大预算预留，不靠猜测实际摘要会足够短。

外发前规划全部提取、归并和成文步骤，证明最坏允许输出仍可进入下一层；压缩层的节点规模严格下降，不设固定累计次数或层数上限。实际摘要已能进入最终请求时立即成文，允许少走预留步骤。每次外发重新计数；结构、引用、覆盖、可见预算、实际压缩或计划失效任一失败即终止，不裁尾、不补写、不修复、不循环。

提取只附该批会话背景，归并不重附原背景，最终成文只附历史日报。辅助材料最多占扣除固定开销后正文空间的 20%，按近到远取完整单元，放不下跳过并继续尝试后续完整单元；不得为了辅助材料新增请求。不存在辅助或回看为 0 不降级；实际存在却被预算排除才记当次已知裁剪。成功来源只单列实际进入请求的历史日期。

## 确认、调度与原子结果

可靠计划上界最多 4 次时可启动；上界超过 4 次（包括只能给出跨越 4 次的范围）须在首笔生成前确认完整有限计划和有依据的次数范围。确认期间输入、配置或设置变化必须重新规划、重新确认，旧按钮不能发送新输入；不估造费用。替换草稿仍受既有保护。

离线规划返回时保留并刷新已打开的关闭／退出等保护面板；返回编辑后仍可从现有进度区查看完整计划，不让规模确认覆盖结束意图。

并发使用启动时保存值，默认 3、范围 1–8。依赖节点等待全部必要上游，乱序完成按原始顺序组装。必要请求失败立即停止派发并取消在途，失败／取消／迟到回调均不能替换旧正文或来源。中间内容在任务结束或取消后释放，不展示、不复制、不保存。

本次全部阶段固定启动时端点、模型、服务默认值、凭据与 O；运行中仅修改 O 的既定窄例外，以及 C／并发／语言／偏好／回看修改，只影响下一次。状态显示真实阶段、层数、计划范围、完成／在途数量和耗时，不展示模型百分比或中间正文。分批本身不降级，质量及原因不进 UI、Markdown 或数据库；遥测仍只接受类型化白名单聚合值。

外发副本脱敏失败沿用既定非阻断提示，等待规模确认和执行期间都可见；失败不显示命中值，用户仍可取消。
