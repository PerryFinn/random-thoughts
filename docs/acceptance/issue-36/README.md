## 固定覆盖与组合

别名只标识验收组合，不代表官方服务、能力或兼容保证。真实端点、query、凭据及别名到实际配置的对应由执行者在授权环境掌握；仓库记录协议、别名、必要模型标识和能力结论，不提交端点、Key、请求／响应、配置导出或私有工作内容。实际模型标识若含私有信息，仅在受控环境核对，公开记录使用组合别名及“已核对／未核对”结论。

各组合只用探测证明支持的可选能力。基础文本未通过不能开始生成；流式或结构化未知／不支持就不使用。未知不等于不支持，拒绝必要控制不能删参数重发；未实测分支继续引用离线覆盖，不声称所有模型或中转兼容。

## 调用规模与预算

以下是待核对的执行方案，不是实测次数或费用承诺：

| 类别 | 计划规模 | 计数方式 |
| --- | --- | --- |
| S01–S06 直接生成 | 3 协议 × 6 场景 × 2 次＝36 任务 | 路径确认为直接且每次成功仅 1 笔生成 HTTP；失败尝试另记 |
| S07–S08 分批生成 | 3 协议 × 2 场景 × 2 次＝12 任务 | 每次提取、片段整合、归并及成文 HTTP 全部计入，不当作单笔请求 |
| 初次配置探测 | 每个校验基线最多 3 笔；三组合各一个基线时合计最多 9 笔 | 基础、流式、结构化另计，不占 48 个生成任务 |
| Codex 合成材料准备 | 尚未确定；若正常交互需要真实 AI 则额外计数 | 不属于日报 48 任务，也不包含在上述探测内 |
| 临时失败／缺陷修复重跑 | 未授权，无法预填数量 | 保留旧记录；列出受影响任务和新规模后单独授权，不自动扩大全部付费验收 |

设 12 次分批任务各自实际用了 `B₁…B₁₂` 笔 HTTP，则无失败尝试时生成合计为 `36 + ΣBᵢ`，还需加配置探测、失败尝试及获授权的重跑／材料准备调用。**48 是生成任务数，不是 HTTP 笔数或累计 token／费用上限。** 未测量填“未测”，不能填 0。

候选起点为：各组合 O＝3,000、并发 3；直接 C＝65,536（I＝50,028），分批 C＝12,000（I＝7,200）。这些只借用既有离线预算示例，不证明实际模型支持或材料一定进入目标路径；须核对真实组合、完整固定指令／格式开销及每笔可见预算。只改 C 不要求重新校验；改 O、模型、端点、凭据或默认值须按实际校验基线重新显式探测，新增基线每个另计最多三笔。

执行前逐组合、逐场景填入记录模板的 C／O／I、能力、计划路径／次数范围及输入规模。S07 要证明同一超长轮次拆片；S08 要证明多层归并和实际辅助裁剪。首笔请求前按产品规则对预计超过四次或无法证明最多四次的完整有限计划确认。实际摘要足够短应立即成文，不能为验收强加归并层；未覆盖目标路径就记该项未完成，后续调整材料／预算先更新版本、核对规模并取得相应授权。

## 逐次判定规则

先核对场景前提、实际语言／路径、完整协议结束和六章节，再人工对照场景的允许事实、必留主要成果／关键阻塞、禁止结论和明确计划。不得将夹具中的 `expected` 回传模型或作为整篇措辞比对；它只供人工理解事实边界。

| 判定 | 必要条件／含义 |
| --- | --- |
| 通过 | 完整有效结果，所选语言／固定六章正确，事实硬违规＝0，主要成果与关键阻塞无遗漏；目标路径实际覆盖 |
| 降级通过 | 同样满足所有硬规则，只存在明确记录的轻微重复、次要细节损失或受控辅助裁剪；不能把主要遗漏降级接受 |
| 失败 | 结构、协议完成或语义硬规则违反；记录类别和合成事实编号，不能以另一次好结果覆盖 |
| 未完成 | 未执行，或取消、网络／限流等临时故障尚无有效结果；保留尝试及请求数，可在授权范围内人工重跑 |
| 受阻 | 缺组合、授权、环境、合格配置或目标路径证据；不是通过，也不凭缺证据断言产品缺陷 |

事实硬违规包括虚构、把请求／尝试当完成、改变状态／时间／责任／意义、历史或背景当当天、静默消解冲突、建议变计划；主要成果或关键阻塞遗漏、语言错误也不可接受。直接、拆片、分批或多层本身不构成降级；不存在辅助、回看为 0 或不合规材料被排除也不构成裁剪损失。

中文六章依次为：今日概览、完成事项、关键产出、决策与思考、问题与风险、明日计划；英文为 Today’s Overview、Completed Work、Key Deliverables、Decisions & Rationale、Issues & Risks、Tomorrow’s Plan。空章分别保留“无明确内容”／“No confirmed content”。概览默认最多三个要点，不引入其他章节之外的新事实；无团队相关内容允许六章全占位成功。

每个实际尝试独立留判定，包括失败／临时故障／取消及未完成。不得平均打分、挑最好一次、隐藏失败或无限重抽。缺陷修复后关联旧记录、修复构建及受影响范围，重跑相应场景；未受影响的付费验收不默认重做。更换端点或模型形成新组合，不能与旧组合拼成同一协议的 16 次合格结果。
