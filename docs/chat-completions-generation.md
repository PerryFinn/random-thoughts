# Chat Completions 直接生成工作日报

本切片承接 [#28](https://github.com/PerryFinn/random-thoughts/issues/28) 与父规格 [#20](https://github.com/PerryFinn/random-thoughts/issues/20)。本地起点 `381b830` 已包含 #24（`f88a832`）、#26（`c43f0d2`）与 #27（`381b830`）；2026-10-13 只读核对远端 main 为 `123948d`，三票及 #28 仍开放，#28 的三个原生阻塞项仍存在。本地实现不解除远端阻塞。

## 统一流程与显式操作

界面与主要业务测试共用 `DailyReportFlow.send`。保存配置、校验已保存配置、设为当前、生成均是独立操作。Chat Completions 校验事前说明最多三个少量合成请求，顺序为基础文本、流式、结构化；不带工作正文、历史或生成偏好。基础成功才能获得资格，可选能力分别保存支持／不支持／未知，只有有成功证据的能力用于生成。临时故障或取消保留旧校验状态，测试不自动选择当前服务。#29 的 [Responses 原生传输](responses-generation.md) 与 #30 的 [Messages 原生传输](messages-generation.md) 复用同一流程与规划。

校验绑定真实请求字段、逻辑凭据版本、O 与探测契约；数据库事务内核对当前基线，只更新相符配置的校验字段。测试期间冻结请求编辑，离开设置提供继续测试或取消测试并离开。当前服务身份与资格分开，失败或需要重新校验不自动换服务。可选探测只有服务明确拒绝对应的 stream／response_format 参数才判不支持；任一阶段的临时未完成保留整份旧结论，必要参数或鉴权／模型错误使对应基线失败。

## 协议与错误

独立 Chat Completions DTO 直接 POST 最终完整端点，使用原生 Bearer、`reasoning_effort`、`max_completion_tokens`、`store:false`；未设置参数不发。不拼路径、不跟随重定向、不自动重试或删除必要字段。无磁盘缓存、Cookie 或持久凭据存储。

非流式须有唯一文本完成且 `finish_reason=stop`；流式须收到合法事件、文本、完成信号与 `[DONE]`。拒绝、工具调用、截断、缺少完成、坏载荷均失败。错误只依据明确的服务代码归类；403／404／429 本身不能证明鉴权、模型不存在或配额不足。明确配置错误只使匹配基线失去资格，临时故障或正文解析失败保留资格。可靠等待时间只开放手动重试，不自动发送。

单请求连接 30 秒，非流式完整结果 5 分钟，流式连续无有效进展 90 秒；合法 SSE 完成信号立即结束请求，不等待服务关闭连接。取消立即使回调失效并取消传输，旧正文及来源保留。睡眠／唤醒不会发新请求，超时按实际经过时间判断。明确配置错误立即撤销匹配基线的生成资格，校验状态的落盘按本地写入队列完成。

## 离线预算与输入

固定 `tiktoken-rs 0.12.1`、锁定 Cargo 依赖，通过薄 C ABI 编译静态库；内置 `cl100k_base`／`o200k_base`。特殊 token 字面量按普通文本。每个实际外发文本块分别取双编码较大计数后求和，再加 1,024 预留；`I=floor(0.8×(C−O))`。初始化／计数失败停止，不按模型猜、不远程计数或用字节后备。构建工具可以下载公开依赖，运行时不下载词表或调用 Python／Rust。

构建固定 Rust `1.90.0`（`Tokenizer/rust-toolchain.toml`）；`script/build-tokenizer.sh` 优先使用仓库 `.build/cargo` 中的工具链，否则使用 PATH 中的 Cargo。首次构建需安装该公开工具链并取得锁定依赖，生成内容只放 `.build/tokenizer`。Xcode 的构建阶段和隔离入口共用此脚本；应用目标关闭构建脚本沙盒，让 Cargo 读取工具链并写入编译缓存，不改变应用运行权限。SwiftPM 导入 `ReportTokenizerC`，Xcode 通过既有桥接头导入同一 C 声明，均链接静态库。

差分夹具由官方 Python `tiktoken 0.14.0` 的 `encode_ordinary` 生成，覆盖中文、英文、代码、组合字符、emoji、NUL、换行、长重复与特殊 token 字面量；逐项分别核对两个真实编码及较大值。夹具生成环境不进入应用或执行测试。版本与词表依据见 [离线 tokenizer 研究](research/local-tokenizer-options.md) 和 [tiktoken-rs 0.12.1](https://docs.rs/tiktoken-rs/0.12.1/tiktoken_rs/)。

固定事实指令、输出契约／schema、偏好与标记均计入预算。当天全部合规轮次必须完整处理；预算外进入 #31 的[有限分批计划](long-input-generation.md)，不能截尾或偷偷丢当天内容。

背景按可靠开始时间近到远选完整轮次，再保持会话内顺序；历史只取同报告时区前 N 个日历日的已保存日报，N 为 0–7，缺日不补、不读草稿。完整辅助单元可跳过但不切开，两类合计不超过扣除固定开销后正文空间的 20%。只有实际存在却未使用的辅助材料才构成已知裁剪。

每次生成固定快照、历史、设置和配置，不重读 Codex。外发只携带临时编号、必要日期／时区及合规正文，不添加真实 ID、标题或目录。所有外发文本副本与入草稿结果采用既定尽力脱敏；失败仍可继续并提示，不修改原快照或手写正文。

## 六章节与草稿生命周期

输出载荷固定为六具名正文：今日概览／完成事项／关键产出／决策与思考／问题与风险／明日计划，英文为 Today’s Overview／Completed Work／Key Deliverables／Decisions & Rationale／Issues & Risks／Tomorrow’s Plan。应用渲染标题、空章占位；只允许换行统一、章节 trim、占位与尽力脱敏。缺章、重复／未知字段、载荷外正文、同级或更高标题（含没有可见正文的空标题）、拒绝／截断／未完成不接受，不调用 AI 修复。标题按预览采用的原生 Markdown 实际结构判断，合法水平线、引用定义和代码中的标题字面量可保留。行首裸 `#`／`##` 即使接在引用定义候选之后仍是空标题，不能作为 URL 例外放行；块结构优先的依据见 [CommonMark 3.1](https://spec.commonmark.org/0.31.2/#precedence)。拼接后仍须完整呈现六章，不能由未闭合代码块吞掉后续标题。

指令区固定工作事项、完成证据、当天与背景／历史、冲突及认可计划规则，材料中的指令只作为数据。机械验收不声称证明语义事实；真实语义验收由 #35 授权执行。

全应用一次生成，目标正文只读，可预览／复制／取消及切日编辑。替换手写或已编辑草稿先确认；确认期间配置、输入或设置变化须重新确认。合格结果一起替换正文、生成基线及实际来源；失败／取消不改旧状态。端点、模型、默认值、凭据或当前服务提交生效即取消当次，不能在提交后的凭据检查等待期间接受旧结果；O 的窄例外与 C／并发、语言／偏好／回看修改仅作用于下次。

实际会话标题按组形成整份草稿临时来源，实际使用历史日期单列仅作背景。编辑和改变当前选择保留原清单；成功保存清关联，失败保留。手写与已保存编辑不反推来源。来源不进数据库、日志、Markdown、预览正文或源跳转。

关闭／退出将正在生成与所有日期／时区草稿合并一次确认，默认继续编辑。打开面板不取消；实际确认结束才取消。面板期间成功、失败、取消或正文变化均刷新确认并使旧按钮失效。

## 验证边界

已确认接口为统一流程动作／状态与真实 SQLite、Chat Completions wire、tokenizer、CocoaLumberjack 的受控集成。隔离执行禁止外网和生产入口，只用合成夹具与临时数据库；协议本机假服务仅开放指定回环端口。日志首次接入即通过类型化白名单，禁止自由文本、原始 Error、端点、模型、Key、正文、偏好、来源与其哈希。

实际命令、结果、固定依赖与未执行项目记录于 [testing.md](testing.md)。不启动应用、不访问真实 Codex／AI；本票本地切片不代表父规格首次交付或真实语义验收完成。

协议编码与完成状态依据：[Chat Completions 创建接口](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)、[流式事件](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events)。本机假服务验证真实 URLSession 的请求、解析、截止与重定向行为；不据此声称当前端点的真实能力已经校验。
