## 本次要回答的问题

在现有固定 860×620 的设置窗口内，怎样组织工作日报、Codex 数据源和 AI 服务配置，使用户清楚区分编辑、保存、测试、设为当前、凭据操作与不可恢复的内容删除？

候选信息架构将使用同一路径与 `?variant=` 比较：

- A：侧栏独立的工作日报与 AI 服务，日报内分组承载常规、Codex 数据源与内容管理。
- B：侧栏单一工作日报入口，内部按主题切换常规、数据源、AI 服务与内容管理。
- C：工作日报概览提供状态摘要与详情入口，配置在详情视图中完成。

已选择 B，A 与 C 作为比较证据保留；完整交互已获用户最终确认。沿用模型监控、蓝牙解锁的现有外壳，原型只模拟新区域。所有状态和凭据均为虚构内存示例，不读取本机 Codex 数据、Keychain 或真实日报，不向服务发请求。

## 讨论树

已确认的第一轮：

1. AI 服务配置显式保存与撤销。
2. 请求端点实际值留空，以 placeholder 显示对应协议的官方完整端点示例，不预填、不提供额外的填入动作。
3. 报告时区分开选择跟随 Mac 与固定模式，固定时区可搜索，始终显示当前有效 IANA 时区。

已确认的第二轮：

4. 先保存再测试；测试只针对已保存配置。
5. 有未保存编辑时，每次离开前要求保存或放弃；保留取消动作以停留当前界面，保存失败不得离开。
6. 新 API Key 随「保存配置」提交，成功才启用；删除已存凭据仍采用独立确认。

已确认的第三轮：

7. 采用 B「日报内分组」：侧栏新增工作日报，其内分为常规、数据源、AI 服务、内容管理。
8. 第三轮曾选择时区与生成设置分开提交；已被第五轮 Q13 的统一保存选择替代，最终原型不再分组提交。
9. 清空全部日报内容仅需一次完整范围确认，列明各类数量及保留项，默认焦点为取消，不要求输入确认文字。

已确认的第四轮：

10. 允许保存不完整的 AI 配置，测试时指出缺项；已有值的格式或范围错误阻止保存并定位字段。
11. 测试期间锁定请求字段；离开前提供继续测试或取消测试并离开。未完成校验被取消时保留原校验状态。
12. 未保存配置编辑必须先保存或撤销，之后才可单独确认删除已存凭据。

已确认的第五轮：

13. 常规页统一「保存更改／撤销更改」，报告时区、输出语言、生成偏好与历史回看天数一起提交。修改时区的后果在对应字段旁预告，列明旧时区所有日期的草稿数量与日期，以及保留范围。
14. 数据源选择通过「保存并检查」生效；失败保留新选择，当前不可用状态与上次成功检查分开呈现。
15. 字段错误、凭据保存／删除失败和测试结论持续行内展示；字段错误定位焦点，成功保存／复制用短提示，危险确认默认取消。

16. 统一保存涉及旧时区草稿删除时，使用一次「保存更改并删除 N 份草稿」确认；切页或关闭时将保存与删除范围合并在同一弹窗，不产生第二层确认。保留前序草稿决议的显式删除确认要求。用户已确认此选择及完整原型与共享理解。

本轮已完成的讨论范围：

- 原型比较：信息架构、设置入口、密度、固定窗口内的滚动与操作位置。
- 编辑与校验：编辑缓冲区、未保存测试目标、切换服务、关闭窗口、当前配置与校验状态的分别呈现。
- 报告设置：语言、生成偏好、历史日报上下文、有效时区变更及草稿保护。
- 凭据与危险操作：掩码、主动显示及复制、替换、独立删除、Keychain 失败、清空全部日报内容。
- 数据源与可访问性：入口、当前状态与上次诊断的区分、焦点、键盘、错误定位和操作反馈。
- 收敛原型与完整共享理解的最终确认。

## 必须继承的决议

- [应用窗口、菜单栏与生命周期](https://github.com/PerryFinn/random-thoughts/issues/7#issuecomment-5306382613)：设置为独立单例固定尺寸窗口，可关闭，不可最小化、缩放或全屏。
- [会话纳入与上下文裁剪](https://github.com/PerryFinn/random-thoughts/issues/6#issuecomment-5306294855)：报告时区为跟随 Mac 或固定 IANA；无效固定时区保留配置并阻止扫描与生成，不静默回退。
- [草稿、保存与历史状态](https://github.com/PerryFinn/random-thoughts/issues/8#issuecomment-5343567258)：手动离开旧有效时区时确认删除其所有日期草稿；目标时区草稿、已保存日报保留；跟随 Mac 自动变更则直接删除旧时区草稿并切换、重新扫描，事后通知数量。
- [AI 服务配置、校验与能力](https://github.com/PerryFinn/random-thoughts/issues/9#issuecomment-5371564460)：三种协议各一份隔离配置，完整 HTTP(S) 端点不追加路径，模型手填；显式测试最多三次请求，基础文本通过是生成资格的前提。保存不联网，测试不切换当前服务；当前身份与生成资格分别表达。
- [生成契约与质量](https://github.com/PerryFinn/random-thoughts/issues/11#issuecomment-5386023653)：中文或英文输出语言优先于生成偏好，模板固定六章节；历史上下文只取同报告时区前 N 个日历日的已保存日报，默认 1、允许 0，最大 N 留给长上下文决策票。
- [日报窗口定型](https://github.com/PerryFinn/random-thoughts/issues/12#issuecomment-5386198166)：日报窗口采用可折叠历史与正文双栏、按需来源抽屉；有效报告时区只读，配置放在设置窗口。
- [Codex 数据源](https://github.com/PerryFinn/random-thoughts/issues/15#issuecomment-5620030195)：一个外部 Codex 可执行文件及一个解析后的数据目录；数据源变更后检查，选择无效不静默回退；当前状态与上次检查诊断分开。
- [最新隐私边界](https://github.com/PerryFinn/random-thoughts/issues/10#issuecomment-5620659159)：HTTP 标注“明文 HTTP”；测试只发送合成文本；凭据仅存本机 Keychain，默认隐藏、主动显示与复制，空输入保留旧值，删除独立确认；更换失败保留旧值，读取失败暂停请求，删除失败不得宣称成功。清空全部日报覆盖所有时区日期的日报、草稿、快照与当前选择，保留设置、凭据和 Codex 原会话。

生成相关失败、取消、重试、排队、限额和恢复的完整策略留给后续对应决策票。本票只定型设置界面的操作与状态呈现，遵守已有失败边界。

## 运行与评审

在本分支的仓库根目录运行：

```bash
rtk proxy python3 -m http.server 8766 --bind 127.0.0.1 --directory prototypes/report-settings
```

打开 `http://127.0.0.1:8766/?variant=B&scenario=first`。无 variant 参数时默认 B。也可直接打开 `index.html`；不需要安装依赖。

底部比较 A / B / C，左右方向键也可切换（输入、选择器、弹窗有焦点时不拦截）。右侧演示工具切换虚构场景，并以可读字段显示每次动作后的相关状态。所有复制、Keychain、数据源检查、请求与删除均为模拟；页面使用 CSP 禁止网络连接和表单外发，不访问任何真实工作内容。

建议点击路径：

- 首次配置：看 placeholder → 输入示例端点、模型和虚构 Key → 保存 → 测试 → 手动设为当前。
- 编辑保护：修改端点后切换服务或菜单 → 取消 / 放弃 / 保存并继续。
- 生成资格：以已校验当前配置开始，保存端点修改 → 当前身份保留、需要重新校验。
- 凭据保护：打开替换输入，勾选模拟 Keychain 失败并保存 → 旧凭据保留、新输入仍在。
- 统一提交：同时修改时区为 America/Los_Angeles、输出语言为 English → 查看字段预告 → 保存更改，或切页触发统一保存入口 → 核对旧时区所有日期的草稿数量和范围 → 一次提交全部常规设置；目标时区草稿与已保存日报保留。采用一次统一确认。
- 取消测试：勾选演示工具「保持测试中」→ 测试配置 → 切换菜单 → 继续测试／取消测试并离开；取消保留之前的校验状态。
- 自动时区：跟随 Mac 时点击模拟变化 → 直接切换、删除旧时区草稿、事后通知。
- 清空内容：内容管理 → 清空 → 核对范围 → 模拟迟到生成结果，内容仍为空。

已通过脚本语法检查和浏览器交互检查：A/B/C 入口比较、首次配置、未保存编辑保护、保存后的资格失效、Keychain 替换失败、手动／自动时区变化、清空及迟到结果；第五轮后补查了常规统一提交及无嵌套确认、测试中取消离开。所有检查均为虚构内存状态。

原型是对以上分轮答案的演示；持久化的物理事务、数据格式、完整生成失败与恢复策略仍由后续票决定，不能从 throwaway 代码推导生产实现。

服务生成默认值的控件范围核对自 [Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)、[Responses](https://developers.openai.com/api/reference/resources/responses/methods/create) 和 [Messages](https://platform.claude.com/docs/en/api/http/messages/create) 的官方 schema（2026-09-11）。范围和枚举只是超集，不能据此承诺任意端点或模型接受这些组合。
